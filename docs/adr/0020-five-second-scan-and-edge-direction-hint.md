# ADR-0020: 스캔 5초 동안 본 물체 중에서만 선정, 자이로로 목표 방향을 기억해 화면 밖이면 엣지 발광으로 유도

- 날짜: 2026-09-16 · 상태: 채택 (ADR-0013·0019의 스캔/힌트를 보강)

## 맥락
실기기 피드백: 타깃을 아예 못 잡는다. 요구는 두 가지.
1. 시작 후 **5초 동안 사용자가 실제로 비춘 물체** 중에서 타깃이 정해져야 한다.
2. 타깃이 정해지면 그 물체 쪽에 빛이 나야 하고, 물체가 화면 밖이면 **화면 상하좌우 가장자리 발광**으로 카메라를 어느 쪽으로 돌릴지 알려줘야 한다.

## 결정
- **스캔 = 정확히 5초**(`SCAN_MS`), 안내에 남은 초를 표시. 후보는 그동안 3회 이상 본 라벨(10초까지 없으면 1회로 완화). 락 문턱 점수는 검출기와 같은 0.4로 내려(0.5 → 0.4) 실물의 0.4~0.6대 점수도 잡히게 한다.
- **목표 방향 기억**: `deviceorientation`(가능하면 `deviceorientationabsolute`)의 alpha·beta·gamma로 후면 카메라가 보는 방향의 heading(북 기준 시계방향)과 pitch를 계산한다(W3C 회전행렬 Rz·Rx·Ry를 기기 −z에 적용). 스캔 중 각 라벨을 봤을 때의 방향을 원형 평균으로 누적하고, 선정된 라벨의 평균을 `home.orient`에 저장한다. 락 중에는 현재 방향으로 계속 갱신(1초마다 저장).
- **엣지 발광**: 플레이 중 락이 없으면 목표 방향과 현재 방향의 차이(heading 차 → 좌/우, pitch 차 → 상/하)로 해당 가장자리에 주황 그라데이션 + 화살표 글리프를 그린다. 8° 이상이면 켜지고 50°에서 최대. 차이가 8° 미만인데도 안 보이면 엣지 없이 "빛나는 물건을 찾아보세요".
- **자이로 없을 때 대체**: 락이 풀릴 때 물체가 화면 중심 기준 어느 쪽으로 나갔는지(`home.lastSide`)를 저장하고 그 가장자리를 0.6 세기로 켠다.
- 상대(비절대) 자이로값은 페이지를 다시 열면 기준이 바뀌므로 로드 시 버린다. iOS는 시작 버튼 안에서 `DeviceOrientationEvent.requestPermission()`을 부른다.

## 이유 (공수)
- 카메라 포즈 추적(WebXR·VIO) 없이 "물체가 어느 쪽에 있나"를 알 수 있는 가장 싼 센서가 자이로다. 회전만 다루므로 사용자가 제자리에서 폰을 돌리는 동작에 정확히 맞는다. 걸어서 이동하면 어긋나지만, 락이 잡히는 순간 방향을 다시 저장하므로 회복된다.
- 화면 좌표의 마지막 이탈 방향은 코드 5줄이고 센서가 없어도 최소한의 유도가 된다.

## 결과
- 헤드리스(자이로 없음): 락이 풀리면 `lastSide`로 엣지 힌트, 합성 `deviceorientation` 이벤트로 heading 차 +60° → 오른쪽 엣지(세기 1.0), pitch 차 −40° → 아래 엣지(0.76) 확인.
- 실기기에서 좌우가 반대로 느껴지면 `edgeHint`의 `dH` 부호를 뒤집는다. 안드로이드 Chrome은 `deviceorientationabsolute`를 주므로 방향이 세션을 넘어 유지된다.
