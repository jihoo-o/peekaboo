# ADR-0013: 공간 스캔 후 대상 물체를 무작위로 골라 저장, "가까움"은 bbox 폭, 발광은 lighter 합성

- 날짜: 2026-09-15 · 상태: 채택 (ADR-0011의 "최초 확정 물체" 규칙을 대체)

## 맥락
요청: (1) 공간을 한 번 스캔 → (2) 인식된 물체 중 캐릭터를 낼 물체를 앱이 값으로 보유 → (3) 그 물체 뒤가 빛남 → (4) 가까워지면 빛이 강해짐 → (5) 5초 이상 인식 → (6) 나타날 듯 말 듯 연출 → (7) 짠! 등장 → (8) 이후 동일.

## 결정
- **스캔**: 카메라 시작 후 최소 6초(`SCAN_MS`) 동안 ALLOWED 클래스의 검출을 `seen[label] = {n, maxW}`로 누적. 6초가 지나고 2회 이상 보인 클래스가 1개 이상이면 종료. 없으면 계속 스캔.
- **대상 선택**: 본 클래스 중 **무작위 1개**를 `localStorage['peekaboo.home'] = {label, seen}`에 저장. 플레이어에게 라벨을 알려주지 않는다(수집 전까지 도감에 `???`). 스캔은 저장값이 없을 때만 다시 한다(초기화 버튼 → 재스캔).
- **가까움**: `near = clamp((bbox.w / videoWidth − 0.15) / (0.6 − 0.15), 0, 1)`. 깊이 추정 없음.
- **발광**: 물체 bbox 중심의 방사형 그라데이션을 `globalCompositeOperation = 'lighter'`로 비디오 위에 그리고, 그 위에 캐릭터, 그 위에 마스크로 잘라낸 물체 픽셀. 결과적으로 빛이 물체 뒤에서 새어 나온다. 세기·반경은 `near`에 비례, 충전 중엔 깜빡임이 빨라진다.
- **등장**: 5초 충전(S7 연출 유지) 뒤 `easeOutBack` 450ms로 튀어나오고 700ms 동안 12방향 버스트 + "짠!" 텍스트.

## 이유 (공수)
- 스캔 결과에서 무작위로 고르는 것이 "앱이 값으로 들고 있는다"를 가장 단순하게 만족하고, 숨바꼭질 게임성이 생긴다. 우선순위 표나 위치 기반 선택은 튜닝 대상만 늘린다.
- 거리 추정에 깊이 모델을 붙이는 대신 bbox 폭을 쓰면 코드 1줄이고, 같은 물체에 대해선 단조 증가라 "가까울수록 강해진다"에 충분하다.
- 발광은 기존 합성 순서(비디오 → 캐릭터 → 오클루전)에 한 단계만 끼워 넣으면 되고, 마스크 오클루전이 이미 "뒤" 효과를 만들어 준다. 밝은 배경에서는 `lighter`가 흰색으로 포화돼 약해 보인다(실내 책상은 대부분 충분).

## 결과
- 헤드리스 검증: scan → play/hidden → charging → peek(pop) → idle, `home = {label:'cup', seen:['cup']}` 저장 확인.
- 같은 클래스의 물체가 여러 개면 모두 빛난다(ADR-0011의 한계 그대로). 스캔에서 물체가 1종만 보이면 그것이 곧 답이다.
