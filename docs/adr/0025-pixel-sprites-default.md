# ADR-0025: 기본 그림을 22×24 픽셀 스프라이트로 — 다마고치 문법의 새 디자인, 부품 조합 생성

- 날짜: 2026-09-18 · 상태: 채택 (ADR-0022의 캔버스 드로잉을 `?skin=drawn`으로 강등, ADR-0023의 우선순위는 유지)

## 맥락
소유자가 다마고치×산리오 가계도 짤을 보여주며 "이런 2D 캐릭터를 완전 똑같이"라고 요청했다. 짤의 캐릭터(마메치·쿠치파치·마이멜로디·키키라라)는 반다이·산리오 IP라 1:1 복제본을 공개 저장소에 넣을 수 없다. 대신 그 그림의 **문법**을 그대로 따른다: 1px 검은 외곽선, 평면 2~3톤, 콩알 눈(2×3)에 흰 하이라이트 1px, 뭉툭한 팔·발, 머리 위 액세서리(후드·리본·모자·귀), 작은 입(ω·활짝·벌림·일자·잇몸).

## 결정
- **`pixel.js`(ES 모듈)**: 22×24 격자에 몸(둥근·달걀·큰)·발·팔·귀 3종·덮개·띠·모자·갈기·꼬리·지느러미·집게·검·책·배지·포셰트·무늬·새싹 부품을 놓고, 외곽선 패스(빈 이웃 또는 위에 얹힌 부품과 맞닿은 픽셀을 검게)를 돌린 뒤 얼굴 부품을 얹는다. 종별 조립은 `DEFS[id]` 한 줄씩. 프레임(눈 뜸·깜빡·실루엣)은 종·색별로 캔버스에 캐시하고 `imageSmoothingEnabled=false`로 정수 배율 확대.
- **렌더 우선순위**: 기기 저장 원본 > manifest 원본 > **픽셀(기본)** > `?skin=drawn`(S17 드로잉) > `?skin=silhouette`. 도감의 미수집 칸도 픽셀 실루엣.
- ADR-0001(app.js 한 파일)의 예외: 스프라이트 데이터·렌더러는 `pixel.js`로 분리해 `docs/preview/pixel-sheet.html`이 같은 코드로 시트를 그린다.
- 특정 기존 캐릭터(다마고치·산리오·먼작귀)의 도트를 옮겨 그리지 않는다. 종의 정체는 색·액세서리·표정 조합으로만 구분한다.

## 이유 (공수)
- 픽셀 격자는 그림 실력 없이도 부품 좌표만으로 일관된 결과가 나오고, 14종 추가·수정이 함수 한 줄이다. 그림 파일이 없으니 무빌드 원칙도 지킨다.
- 다마고치 문법은 작은 화면에서 실루엣이 또렷해 AR 위에 얹었을 때 S17 드로잉보다 잘 읽힌다.

## 결과
- 시트: `docs/verify/s20-pixel-sheet.png`. 등장·탭·도감·공유 사진을 픽셀 렌더러로 재검증.
- 원본 에셋을 받으면 그대로 우선 적용되며 픽셀은 사라진다(ADR-0023).
